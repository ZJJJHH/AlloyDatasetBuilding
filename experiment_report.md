# Alloy Inverse Design Q&A + Scoring Dataset Construction — Experiment Report

> This report is written based on the complete experimental content and statistical data of the `AlloyDatasetBuilding` project, serving as a detailed reference for the experimental section of the paper. The report covers experimental setup, dataset construction pipeline, scoring system design, experimental results and analysis, and other comprehensive contents.

---

## 1. Experiment Overview

### 1.1 Experimental Objectives

Construct a professional Q&A and scoring dataset for titanium alloy inverse design, containing four cognitive dimensions of professional questions, reference answers generated by multiple models, and a complete dual-round scoring system. The dataset aims to provide a benchmark for evaluating the Q&A capability of large language models in the field of materials science.

### 1.2 Experimental Pipeline

The experiment is divided into six stages:

```
Stage 1: RAG Knowledge Base Construction → Stage 2: Question Generation → Stage 3: Answer Generation → Stage 4: Round 1 Scoring + Optimization → Stage 5: Round 2 Scoring → Stage 6: Data Post-processing and Statistical Analysis
```

### 1.3 Experimental Environment and Models

**Large Language Models Used**:

| Stage | Model | Purpose |
|-------|-------|---------|
| Question Generation | DeepSeek-V3.2 (deepseek-V3.2) | Generate professional questions across four dimensions |
| Answer Generation | DeepSeek-V3.2 | Generate reference answers |
| Answer Generation | Qwen3.5 (qwen3.5) | Generate reference answers |
| Answer Generation | MiniMax-M2.5 | Generate reference answers |
| Round 1 Scoring | GLM-5 (glm-5) | Score answers from 3 models + generate optimized answers |
| Round 2 Scoring | DeepSeek-R1 (deepseek-r1) | Final scoring of answers from 4 models |

**API Call Parameters**:
- Question Generation: temperature=0.7, max_tokens=200-300
- Answer Generation: temperature=1.0, top_p=0.95, max_tokens=1500
- Round 1 Scoring: temperature=1.0 (GLM-5), max_tokens=2000
- Round 2 Scoring: temperature=0.5 (DeepSeek-R1), max_tokens=5000

### 2.7 RAG Retriever Design

The **RAGRetriever class** (`rag_retriever.py`) implements multi-dimensional keyword matching retrieval:

1. **Index Construction** (`_build_index`):
   - `alloy_code_index`: Based on alloy grades (TC series, TA series, TB series, Ti-Al-V formats)
   - `application_index`: Based on application domain keywords
   - `performance_index`: Based on performance data types
   - `embedding_index`: Based on embedding text keywords

2. **Relevance Scoring Algorithm**:
   ```
   relevance_score = 
       2.0 × alloy_match_score +
       1.5 × application_match_score +
       1.0 × performance_match_score +
       0.5 × keyword_overlap_score
   ```

3. **Retrieval Strategy**: Returns Top-K (K=3 for question generation, K=10 for answer generation) most relevant records

### 4.3 Answer Generation Strategy

Adopts a "unified framework + differentiated generation" strategy:

- **Base class** `AnswerGenerator`: Responsible for RAG retrieval, context building, result saving, and other common logic
- **Subclass differentiation**:
  - `WhatIfAnswerGenerator`: Focuses on scheme comparison, outputs "Scheme A / Scheme B / Scheme selection recommendation" structure
  - `CausalAnswerGenerator`: Focuses on mechanism analysis, outputs "Causal relationship confirmation / Action mechanism / Influencing factors / Engineering guidance" structure
  - `MitigationAnswerGenerator`: Focuses on systematic diagnosis, outputs "Root cause / Detection methods / Repair & prevention" three-dimensional framework
  - `PathwayAnswerGenerator`: Focuses on path completeness, outputs "Initial state / Evolution process / Intermediate states / Final state / Control strategy" complete path

**Answer Generation Prompt Structure**:
```
Question text + Design scenario / Analysis target information + RAG retrieval reference data + Answer format requirements
```

#### 5.1.3 Scoring Pipeline

```
Load questions and answers from 3 models → Build scoring prompts (including scenario info) → Call GLM-5 for multi-dimensional evaluation → Extract scoring details and reasoning → Generate optimization prompts → Call GLM-5 to generate comprehensive optimized answer
```

**Optimization Strategy**:
1. Comprehensively analyze the strengths and weaknesses of each answer (based on scoring reasoning)
2. Extract the advantageous parts of each answer
3. Compensate for the deficiencies in each answer
4. Generate the optimal comprehensive answer (GLM-5 optimized answer)

## 9. Key Experimental Techniques Summary

### 9.1 RAG Retrieval Enhancement

- **Data scale**: 56,515 titanium alloy structured data records
- **Indexing strategy**: Multi-dimensional keyword indexing (alloy grades + application domains + performance types + embedding text)
- **Retrieval performance**: Based on relevance-weighted scoring (composition weight 2.0 > application 1.5 > performance 1.0 > text 0.5)
- **Application effects**: Ensures all generated questions and answers are supported by real data, improving professionalism and traceability

### 9.2 Multi-Model Collaboration

- **5 different large language models** participated in dataset construction: DeepSeek-V3.2, DeepSeek-R1, Qwen3.5, MiniMax-M2.5, GLM-5
- **Clear division of labor**: Question generation (1 model), answer generation (3 models), scoring and optimization (2 models)
- **Model complementarity**: Through multi-model answer generation + comprehensive optimization, achieved higher quality answers than any single model

### 9.3 Dual-Round Scoring Mechanism

- **Round 1 (GLM-5)**: Multi-dimensional scoring + optimized answer generation (with detailed scoring reasoning)
- **Round 2 (DeepSeek-R1)**: Independent verification scoring (stricter standards, temperature=0.5)
- **Cross-validation**: Through scoring by two different models, evaluating scoring consistency and reliability
- **Fusion strategy**: Stratified weighted fusion based on scoring gaps

### 9.4 Engineering Practices

- **Checkpoint resume**: Intermediate results saved periodically, supporting continuation after interruption
- **Error handling**: Single record failure does not affect the overall process
- **API traffic control**: Configurable call intervals and batch sizes to avoid API rate limiting
- **Encoding consistency**: Unified use of utf-8-sig encoding to avoid garbled text issues

## 10. Discussion and Limitations

### 10.1 Key Findings

1. **What-if questions are the most challenging**: Best average score of only 84.72, far below other types (92-93 points), indicating that open-ended inverse design tasks still pose significant challenges for current LLMs
2. **Multi-model answer quality ranking is consistent**: GLM-5 Optimized > DeepSeek-V3.2 > Qwen3.5 > MiniMax-M2.5, this ranking is consistent across all four question types
3. **Answer optimization is significantly effective**: GLM-5 achieves an average improvement of 3-5 points (relative to the best standalone model, DeepSeek) by integrating advantages from multiple answers
4. **Two-round scoring consistency is moderate**: Pearson correlation ranges from 0.1-0.7, with systematic biases between different scoring models
5. **Data support is a common weakness**: Especially for What-if questions, all models score only about 60% on the "Data Support" dimension

### 10.2 Limitations

1. **Single domain coverage**: The dataset only covers the titanium alloy domain and has not yet been extended to aluminum alloys or other alloy systems
2. **Scoring subjectivity**: The LLM-as-Judge approach has inherent subjectivity and inconsistency
3. **Answer quality ceiling**: The quality of optimized answers is bounded by the quality ceiling of the original answers
4. **Chinese language specificity**: The dataset is built on Chinese materials science literature; cross-linguistic generalization capability is unknown
5. **Lack of human annotation validation**: Scoring relies entirely on automated LLM evaluation, lacking gold-standard annotations from human materials science experts
