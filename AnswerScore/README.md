# Answer Scoring and Optimization System

This directory contains the first-round scoring and optimization code for titanium alloy question answers. It scores answers generated by three large language models (DeepSeek, Qwen, MiniMax) and generates optimized answers based on the scoring results.

## System Architecture and Technical Implementation

### Core Modules

| Module | Function | Implementation File | Technical Details |
|--------|----------|---------------------|-------------------|
| Configuration Management | Manage scoring models, scoring dimensions, and weights | `config.py` | Supports multi-model configuration, custom scoring dimensions and weights |
| Scoring Client | LLM API call wrapper | `score_client.py` | Supports DeepSeek, Qwen, GLM, MiniMax and other models, including auto-retry and error handling |
| Score Generator | Core scoring logic | `score_generator.py` | RAG-enhanced scoring, multi-dimensional score calculation |
| RAG Retriever | Scoring-specific retrieval | `score_rag_retriever.py` | Hybrid semantic and keyword-based retrieval, automatically filters the most relevant alloy data |
| Optimization Generator | Generate optimized answers | `optimize_generator.py` | Synthesizes advantages from multiple model answers to generate the best answer |
| Batch Processor | Batch scoring and management | `run_all.py` | Incremental saving, checkpoint resume, intermediate file management |
| Data Source Loader | Load and process alloy data | `data_source_loader.py` | Supports loading alloy data from JSONL files, providing data preprocessing |

### Technical Features

1. **Multi-Model Support**: Supports DeepSeek, Qwen, GLM, MiniMax and other LLMs for scoring
2. **RAG-Enhanced Scoring**: Uses a specialized RAG retriever to retrieve relevant alloy data from Ti_data.jsonl for scoring support
3. **Incremental Processing**: Saves intermediate files every 10 samples, supports checkpoint resume
4. **Multi-dimensional Scoring**: Designs specialized scoring dimensions and weights for different question types
5. **Answer Optimization**: Generates comprehensive optimized answers based on the strengths of multiple model answers
6. **Detailed Error Handling**: Includes API call error handling, retry mechanism, and detailed error logging
7. **Statistical Analysis**: Provides detailed API call statistics and scoring result analysis

## Feature Introduction

### Scoring System
- Multi-dimensional scoring for answers generated by three LLMs (DeepSeek, Qwen, MiniMax)
- Supports evaluation schemes for five question dimensions:
  - **What-if**: Feasibility, Technical Rationality, Data Support, Scheme Diversity, Expression Clarity
  - **PropertyLookup**: Numerical Accuracy, Unit Correctness, Data Source Completeness, Test Condition Matching
  - **Causal**: Causal Correctness, Mechanism Explanation Depth, Terminology Usage, Logical Coherence
  - **Mitigation**: Diagnostic Accuracy, Solution Feasibility, Systematicalness, Operability
  - **Pathway**: Path Completeness, Mechanism Clarity, Logical Coherence, Professional Depth

### Optimization System
- Synthesizes the strengths and weaknesses of answers from three LLMs to generate the best answer
- Extracts advantageous parts of each answer based on scoring reasoning
- Compensates for deficiencies in each answer

## Configuration

### Scoring Model Selection

Modify the `SCORE_MODEL` variable in `config.py`:

```python
SCORE_MODEL = 'qwen'  # Options: 'deepseek', 'qwen', 'glm', or 'minimax'
```

### Scoring Dimension Configuration

Each question type has different scoring dimensions and weights, viewable and modifiable in `config.py`:

- `WHAT_IF_SCORE_CONFIG`
- `PROPERTY_LOOKUP_SCORE_CONFIG`
- `CAUSAL_SCORE_CONFIG`
- `MITIGATION_SCORE_CONFIG`
- `PATHWAY_SCORE_CONFIG`

## Quick Start

### 1. Install Dependencies

```bash
pip install openai>=1.0.0 tqdm
```

### 2. Configure API Keys

In `config.py`, configure the API keys for the scoring LLMs:

```python
# DeepSeek API configuration
DEEPSEEK_CONFIG = {
    "api_key": "YOUR_API_KEY",
    "base_url": "<deepseek-api-endpoint>",
    "model": "deepseek-chat",
    "max_tokens": 2000,
    "temperature": 0.7,
    "retry_count": 3,
    "delay_between_calls": 1.0
}

# Qwen API configuration
QWEN_CONFIG = {
    "api_key": "YOUR_API_KEY",
    "base_url": "<qwen-api-endpoint>",
    "model": "qwen3.5-397b-a17b",
    "max_tokens": 2000,
    "temperature": 0.7,
    "retry_count": 3,
    "delay_between_calls": 1.0
}

# GLM API configuration
GLM_CONFIG = {
    "api_key": "YOUR_API_KEY",
    "base_url": "<glm-api-endpoint>",
    "model": "glm-4-flash",
    "max_tokens": 2000,
    "temperature": 0.7,
    "retry_count": 3,
    "delay_between_calls": 1.0
}

# MiniMax API configuration
MINIMAX_CONFIG = {
    "api_key": "YOUR_API_KEY",
    "base_url": "<minimax-api-endpoint>",
    "model": "abab6.5s-chat",
    "max_tokens": 2000,
    "temperature": 0.7,
    "retry_count": 3,
    "delay_between_calls": 1.0
}
```

### 3. Run Scoring and Optimization

#### Batch Process All Question Types

```bash
cd /path/to/AlloyDatasetBuilding/AnswerScore
python run_all.py
```

#### Process Specific Question Types

```bash
python run_all.py --types "what_if,property_lookup"
```

#### Process a Range of Questions

```bash
python run_all.py --start 0 --end 100
```

#### Clean Up Intermediate Files

```bash
python run_all.py --clean
```

## Intermediate File Management

- The system saves intermediate files incrementally every 10 samples
- Intermediate files are saved in the `AnswerScore/incremental/` directory
- After completion, intermediate files are used to overwrite the original question files
- Use the `--clean` parameter to clean up intermediate files

## Important Notes

1. **API Call Costs**: The scoring and optimization process requires API calls to the scoring LLM; please manage costs
2. **Delay Settings**: The system defaults to a 1-second delay between API calls to avoid rate limiting
3. **Error Retries**: The system automatically retries failed API calls up to 3 times
4. **Intermediate Files**: Regularly back up intermediate files to prevent data loss
5. **Scoring Model**: It is recommended to use high-quality scoring LLMs (such as GPT-4, Claude, etc.)
6. **Optimized Answer Not Scored**: The optimized answer is generated by the scoring LLM, so it does not include a scoring field, awaiting subsequent scoring by another LLM
7. **RAG Retriever**: The system uses a specialized RAG retriever (score_rag_retriever.py) to retrieve relevant alloy data from Ti_data.jsonl for data corroboration during scoring

## FAQ

### Q: Scoring results not saved to the original file?
A: Check the `AnswerScore/incremental/` directory for intermediate files. After full completion, they will automatically overwrite the original file.

### Q: How to reprocess a specific question type?
A: Simply run `python run_all.py --types "question_type"`.

### Q: How to process only some questions?
A: Use the `--start` and `--end` parameters to specify a range, e.g., `--start 0 --end 100`.

### Q: Why doesn't the optimized answer have a scoring field?
A: The optimized answer is generated by the scoring LLM. To avoid the "scorer" and "examinee" being the same LLM, the optimized answer does not include a scoring field, awaiting subsequent scoring by another LLM.

### Q: How are relevant alloy data obtained during scoring?
A: The system uses a specialized RAG retriever (score_rag_retriever.py) to retrieve relevant alloy data from Ti_data.jsonl. The retriever automatically retrieves the top 3 most relevant alloy records based on alloy composition, performance category, test conditions, and other information in the question scenario, providing them as scoring evidence to the scoring LLM.
